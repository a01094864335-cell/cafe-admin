## 저장과 복원

- 장부 키: `cafe-admin-public-v1`. JSON `version`은 **2**이며 키 이름의 v1과 다르다.
- 테마 키: `cafe-admin-public-theme`. 이전 자료 다운로드 키: `cafe-admin-unused-legacy`.
- 시작 시 JSON 파싱·검증에 실패하면 빈 장부를 임시 표시하고 원래 값을 덮어쓰지 않는다.
- 저장은 전체 스냅샷을 검증 후 `setItem`한다. 실패하면 이전 메모리·저장 데이터를 유지하고 모달 입력을 남긴다.
- 복원은 20 MiB 이하 v2 JSON에 대해 확인 후 전체 교체한다. 배열별 최대 50,000개, 배열 전체에 걸친 ID 중복 금지, 매출/근무의 날짜 중복 금지.
- 백업은 전체 장부에 `lastBackup`을 찍은 JSON 다운로드다. CSV에는 수식으로 해석될 수 있는 문자열 이스케이프가 있다.
- 브라우저 저장은 origin별이다. 기존 file URL 장부가 개발 서버로 자동 이동하지 않는다. 기존 앱에서 JSON 백업 후 새 화면에서 복원해야 한다.
- 현재 로컬 저장 인터페이스는 동기식이다. W08의 원격 저장에서는 Promise 기반 명령, 로딩/실패 상태, 버전·중복 요청 처리를 추가해야 한다.

## 필드와 관계

| v2 영역 | 주요 필드 | 의미와 이전 주의점 |
| --- | --- | --- |
| sales | id, date, card/cash/transfer, note | 날짜당 1건. 채널 금액은 정수 또는 null, 환불 음수 허용 |
| purchases | id, date, group, vendor, item, amount, note | `월별 구매`와 `재료 외 지출`을 한 배열에 저장 |
| incomes | id, date, item, amount, note | 기타수익. 매출과 별도로 수익에 포함 |
| payroll | id, date, start/end, breakMinutes, note | 직원 ID가 없고 날짜당 1건인 단일 직원 전제 |
| employment | hireDate, firstWeek, endDate, weeklyHours, holidayDay, normalDays, rates | 장부 전체의 직원 1명 설정. 연도별 시급, 계산 범위 start/end 포함 |
| weeks | 주 시작일 → agreed, confirmation, note | 약정시간 조정과 개근 확인, 근무시간만으로 자동 확정하지 않음 |
| monthlyExtras | 월 → 금액 또는 null | 월 마지막 날이 조회 기간에 포함될 때 수당 반영 |
| comparisons | 월 → reported, note | 대조용 매출이며 실제 수익에 포함하지 않음 |
| inventory | id, name, qty, min, unit, cost, supplier | 독립 수량 장부. 구매와 연결된 재고 이동 이력이 없음 |
| checks, lastBackup | 확인 항목, 백업 시각 | 운영 UI 상태 |
| source, modified 등 | 선택적 원본 출처 메타데이터 | 복원·수정 시 유지. 서버에서는 신뢰하는 권한 정보로 사용하지 않음 |

날짜는 `YYYY-MM-DD` 문자열, 날짜 계산은 UTC 정오를 기준으로 한다. 초기 조회 월은 기기 현지 날짜다. 금액은 원 단위 정수, null은 미입력, 0은 입력한 0원이다. 기본 고용 계산 범위는 2026-10-01~2027-09-30, 시급 기본값은 없다.

## 보존할 계산

1. 일매출 = 카드 + 현금 + 이체. 세 값 모두 null이면 매출 미입력이며 메모만 저장 가능하다.
2. 실근로 = 경과 분 - 무급휴게. 근무일별 기본급은 원 단위 올림. 시급 누락·불완전 입력은 null 상태를 유지한다.
3. 퇴근 24:00, 같은 달 자정 넘김을 지원한다. 월 경계를 넘으면 날짜별 분리 입력을 요구한다.
4. 주휴는 기존 약정시간 평균, 확인 상태, 입퇴사 기간, 주휴일 연도의 시급으로 계산한다. 주휴일이 조회 기간 안에 있을 때 반영한다.
5. 월 기타수당은 월말 기준, 매출 대조 값과 재고 평가는 손익에 더하지 않는다.
6. 간이 잔액 = 매출 + 기타수익 - 구매 - 재료 외 지출 - 기본급 - 반영된 주휴 - 기타수당. 미확정 급여가 있으면 pending을 유지한다.

이 항목은 기존 프로그램 재현 기준이며 노무·세무 적합성 검증이 아니다. 기존 문구나 계산 규칙을 새 법률 판단으로 수정하지 않았다.

## 이후 단계에서 별도 처리할 한계

- 근무·수당·주휴 설정 모두 직원 1명 전제다. 가져오기에서 소유자가 지정한 직원 1명에 연결하고 계정 연결을 강제하지 않는다.

- 실제 개인정보 제거 자료와 운영자 합계 대조는 파일럿 전 별도로 필요하다.
