# 공유 장부 시트 다운로드

`자료 이전 · 백업`에서 소유자가 `시트로 내려받기 (.xlsx)`를 선택하면 기존 v3 백업의 일관된 전체 스냅샷을 사용해 파일을 준비한다. 준비가 끝나면 `엑셀 시트 내려받기` 링크로 저장한다.

현재 카페의 전체 자료이며 화면의 조회 기간·검색과 무관하다. 안내, 매출, 매입, 비용, 기타 수입, 직원, 근무, 급여 설정, 연도별 시급, 주휴 확인, 기타 수당, 매출 대조, 재고 품목, 재고 이동을 별도 탭으로 제공한다. 삭제 자료는 제외하고 재고 정수 1/100 단위를 실제 수량으로 변환한다. 미입력 휴게·약정시간은 빈 셀로 보존한다. 급여 탭은 원본 기록이며 확정 급여 계산표가 아니다.

숫자·빈칸·텍스트를 명시적으로 구분하는 오프라인 XLSX 생성기를 사용한다. 텍스트를 수식으로 실행하지 않으며 인증·계정 식별자는 내보내지 않는다. 기존 소유자 권한, 페이지네이션, 스냅샷 잠금/완료/취소와 크기 제한을 재사용한다. DB migration과 로그인 설정 변경은 없다.

배포 전 기존 서비스의 `cloud-CZe7gmIv.js`와 보존한 로컬 빌드의 바이트 일치를 확인했다. 기존 미커밋 대시보드·정렬·직원 화면 변경을 별도 보존 커밋에 담아 서비스 기능의 후퇴를 방지했다. 기존 가져오기 테스트는 최신순 정렬에서 특정 날짜를 위치 대신 날짜로 찾도록 수정했다.

검증: `pnpm check:backend`, `PLAYWRIGHT_CHANNEL=chrome pnpm test:cloud`, `node --test tests/sheet-export.test.mjs`. 실제 브라우저 다운로드, 완료 후 잠금 해제, 빈 장부, 수치·빈칸·한글·XML·ZIP CRC·수식 형태 텍스트·삭제 행 제외·재고 단위·계정 식별자 제외를 확인한다.

대상: 기존 `cafe-admin-test` Worker와 기존 D1. 사용자가 현재 서비스의 갱신을 요청했으며 별도 운영 DB를 생성하거나 자료를 이전하지 않는다. 배포 전 활성 버전: `ebb8dc14-083e-4507-abea-a7c550ba276b` (코드 롤백 대상). 기존 두 secret을 유지한다.

CI에서 여러 Miniflare DB 테스트가 성능 측정과 동시에 실행되어 10명 부하의 2초 기준을 넘었다. D1 테스트 파일은 `--test-concurrency=1`로 격리 실행한다. 내부의 10명 동시 사용자 시나리오와 2초 성능 기준은 유지한다.
