# W08–W11 공유 장부 구현 현황

2026-10-08, `codex/cloud-ledger`. 전체 계획 완료가 아니라 로컬 구현·검증 기록이다. 실계정 OAuth, 원격 D1 및 실제 파일럿은 별도 검증해야 한다.

## 화면과 저장

`/cloud.html`을 공유 서비스 진입점으로 추가했다. 기존 로컬 장부와 계산 소스는 보존한다. 카페별 권한과 활성 dataset을 서버가 결정하며 브라우저에 장부를 영구 캐시하지 않는다. 카페 전환 시 이전 요청의 응답을 무시하고 미저장 입력을 확인한다. 60초 활성 탭 갱신, 재시도 시 동일 요청키, 실패 시 입력 보존을 적용한다.

매출·매입·비용·기타 수입·재고·직원·근무·급여·손익·멤버 관리 화면을 연결했다. Google 로그인, 초대 링크 생성/취소/수락, 역할 변경, 참여 해제, 소유권 이전, 허용된 사용자의 카페 생성을 지원한다. 초대 링크는 fragment에 담고 OAuth 중에는 10분 HttpOnly 쿠키로 보존한다. 자동 메일 발송은 없다.

## API 보완

- 장부 CRUD는 날짜·정수 원·null과 0·버전·논리 삭제·커서 범위를 검사한다. 매출 충돌 응답은 권한 재검증 뒤 최신 DTO를 포함한다.
- `/inventory/items`와 `/inventory/movements`는 품목 등록과 이동 이력을 같은 batch에 저장한다. 수량 직접 수정은 허용하지 않는다. 수량은 정수 hundredths로 전달한다.
- 매입의 선택적 `stock: {itemId, deltaHundredths, expectedItemVersion}`은 최종 연결 수량을 나타낸다. 생략은 기존 연결 유지, null은 연동 해제다. 수정은 차액 이동, 삭제는 반대 이동을 추가한다. 품목 교체도 동일 batch에서 처리한다. 현재 재고를 건드린 동시 요청은 전체 충돌로 취소한다.
- 명령 ID를 계획 함수에 전달하고 기존 카페 명령을 먼저 연결하여 이동 이력의 operation FK가 batch 안에서 유효하도록 했다. 신규 카페 생성의 기존 원자성은 유지한다.
- 직원 연결은 현재 카페의 활성 멤버만 가능하다. 본인 근무 API는 actor의 연결 직원을 서버에서 결정한다. 임의 employeeId 입력은 거부하고 연결 해제 후 접근도 거부한다.
- 급여 설정은 적용 기간별로 보존하고 겹침을 거부한다. 새 기간 PATCH는 id/expectedVersion 생략, 기존 기간은 둘 다 지정한다. 주별 확인·월별 수당 PUT도 새 기록은 expectedVersion 생략, 기존 기록은 현재 버전을 지정한다. 연도별 rates는 전체 교체다.
- 급여는 기존 계산 모듈을 adapter로 호출한다. 기간별 급여 및 주휴는 각 적용 기간에 한 번만 반영하고 월별 수당은 월말에 한 번 반영한다. 미설정·미확정은 pending으로 드러낸다. 기존 계산 상수는 변경하지 않는다.
- `/payroll`과 `/dashboard`는 from/to 필수, 최대 366일 간격이다. 한 읽기 batch의 revision과 활성 dataset으로 집계하고 반환 전 접근을 다시 검사한다.

## 로컬 증거

`pnpm check:backend`와 `PLAYWRIGHT_CHANNEL=chrome pnpm test:cloud` 통과: 기존 계산/저장 회귀 20, 서버 단위 4, D1 35, Worker 통합 2, 실제 브라우저 시나리오 1. 이후 변경은 재검증해야 한다.

두 브라우저 매출 공유, 두 카페 서로 다른 권한, 미저장 전환 확인, 390px 모바일 폭을 검증했다. 브라우저에서 매입·재고·직원·근무·급여 설정 저장과 초대 생성/취소를 실행했다. 재고 부분 저장 실패, 중복 재시도, 동시 버전 충돌, 다른 카페/임시 dataset 격리, 직원 본인 접근 및 연결 해제, 기존 v2 샘플 급여/주휴/기타수당 일치를 D1에서 확인했다.
