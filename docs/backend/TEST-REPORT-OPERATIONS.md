2026-10-09, `codex/cloud-operations`의 W13 후속 구현. Node 24.19, Wrangler 4.148, 로컬 Miniflare D1, macOS Chrome 격리 프로필. 실제 계정의 브라우저 프로필이나 OAuth 쿠키를 테스트 코드로 가져오지 않았다.

## 자동 검증

- `pnpm check:backend`: 단위 20 + 서버 7 + D1 46 + Worker 2 = 75개 통과. TypeScript/Vite 빌드와 Worker dry-run 통과.
- 서버 7개 중 Python 복구 검증은 내부 3개 시나리오를 실행한다. 전체 DB 동일성, 한 카페 복구/다른 카페/멤버십 보존, 잘못된 입력의 전체 롤백을 검증했다.
- `PLAYWRIGHT_CHANNEL=chrome pnpm test:cloud`: 확장 시나리오 통과. 두 가상 사용자 공유, 역할 차단, 미저장 입력, 생성/이전/다운로드, 재고 저장 실패 후 재시도, 이미 서버에서 삭제됐으나 응답을 잃은 재시도, 직원 전환 뒤 늦은 급여 설정 응답, 이력 화면, 데스크톱 1360px·모바일 390px.
- 이력 조회: 카페별 cursor, 최신순, 소유자/관리자만 조회, 역할 변경 즉시 차단, 원본 payload·토큰·이메일 제외.
- 요청 제한: 같은 사용자 동시 요청의 마지막 1자리만 허용, 초과 시 거래 변경 없음, 다음 분 초기화. HTML 429 응답과 클라이언트 재시도 제한, 같은 쓰기 키 보존.

## 동시 사용 및 쿼리 예산

가상 계정 10개가 같은 카페에서 동시에 매출 조회·연간 요약·비용 등록을 각 3회 수행했다. 총 90개 요청, 각 종류 30개. 초기 매출은 전체 DB 368행(대상 카페 활성 366행), 직원/재고는 기본 가상 fixture다. 테스트 중 새 비용 30개를 만든다.

| 경로 | 로컬 p95 | 최대 SQL/요청 | 기록된 batch/all 읽기 행 합계 | 쓰기 행 합계 |
| --- | ---: | ---: | ---: | ---: |
| 매출 목록 | 305ms | 4 | 1,530 | 0 |
| 연간 손익 | 633ms | 16 | 11,250 | 0 |
| 비용 저장 | 498ms | 21 | 855 | 750 |

이는 전체 백엔드 회귀 테스트와 함께 실행한 로컬 결과다. `first()` 메타데이터가 없는 호출의 행 사용량은 합계에서 빠져 있으므로 청구량 계산에 사용하지 않는다. 원격 네트워크 지연·Workers CPU 10ms·실제 파일럿 데이터 규모는 별도 측정이 필요하다.

재고 10행 chunk에서 SQL 예산 50개 초과를 재현했다. 원본 ID 매핑을 단일 bound multi-row insert로 합쳐 중복 ID 제약과 원자성을 유지하면서 해결했다. 가져오기 생성/최대 chunk/검증/취소/다시 가져오기/적용/백업의 최대 실행 SQL은 **43개**다. 테스트 meter가 50개 초과 시 즉시 실패하므로 batch를 한 번으로 잘못 세지 않는다.
